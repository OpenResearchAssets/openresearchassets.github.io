# 公开产品定位与真实功能

OpenResearchAssets 是**科研全过程可发现、可理解、可复用的资产库**，服务人类和有文件/网页读取工具的 AI。首批高质量积累集中在 AI / CV / Robotics 的科研视觉表达与工作流，但分类架构不限于论文绘图。

## 网站信息架构（当前权威规则）

用户面向的三个**内容入口**是 **精选 Curated / 社区 Community / 发现 Findings**；**投稿 Contribute** 是独立行动按钮，不是平级的第四类内容库。不要把 Gallery、可编辑 SVG、Skills、质量自查、设计原则、For AI 当作同层级产品页面。

| 一级入口 | 内容 | 资产存储 / 操作 |
|---|---|---|
| 精选（首页 `index.html`） | Gallery（优秀论文图、项目主页、可编辑 SVG）与 Skills / Workflows 两类正式资产；页面展示仅服务这两条主线 | `catalog/index.json`，人工审核；资产详情 `asset.html?id=...` |
| 社区（`community.html`） | 所有人发现与讨论未精选投稿，按最新、点赞与类型筛选；不将点赞数当作精选质量 | GitHub Issue Form + Issues API；不维护第二套资产目录 |
| 发现（`findings.html`） | 自动发现 Hugging Face 论文趋势、GitHub Trending、热门 Skills 与近期 Workflows；独立来源、实时性、趋势口径透明 | `tools/update_findings.py` 定时生成 `data/findings.json`，不改变人工精选或社区投稿数据 |
| 投稿（`contribute.html`） | 唯一醒目的投稿入口；三项必要说明（原作者/来源、用途、版权） | GitHub Issue Form，无须仓库权限 |

辅助能力 `quality.html`、`principles.html`、`for-agents/` 与版权政策继续保留，但是从**公共页脚**进入，不与三入口竞争。历史 `examples/` 等教学材料保留旧链接，默认不重新推广成主产品。

Findings **不等于编辑背书**，不会自动写入精选库，不自动伪造用户投稿。抓取失败保留旧快照时间或明确不可用。数据与来源定义参见 [FINDINGS.md](FINDINGS.md)。三类入口持续保持中文优先、英文切换。

站点公共导航/公共页脚的**唯一代码实现**是 `js/navigation.js`（响应式配套 `css/site.css`），所有页面只声明带 `data-page` 的空 `#site-nav` 挂载点；语言切换按统一状态更新。禁止复制页面独立导航，也不增加多个互相矛盾的 IA 文档。 `index.html` 的可编辑 SVG 保留为 Gallery 子分类，放在 Skills 之前；Community 的入口说明尽量简短，让用户先看到实际投稿。维护已设计好的真图及 39 条精选档案，不为收敛导航而重新绘图。

## 选品原则：两个核心资产方向

Open Research Assets 的公开首页只突出 **Research Gallery（高审美科研配图、项目主页和可编辑图）** 与 **Research Skills / Workflows（能够完成具体任务的能力资产）**。论文方法或实验解读仅作为必要的来源、科学事实和设计参考辅助，**不再作为首页、组织主页或增长方向的主产品**；既有页面可以保留旧链接，但不主动作为产品入口推广。

Skills / Workflows **只精选两条正式路径**：

1. **高热度 / Popular**：真实 GitHub 项目、明确用途、公开仓库原始链接和可核对 Star；Star 表示社区关注，不表示实测质量。记录 `curation.track=popular`、`github_repo`、`stars_snapshot` 与 `stars_checked_on`；网页优先实时更新，失败时展示注明日期的快照。禁止为拉数量混入与科研任务无关的仓库或将整个 Skill 目录冒充某个 Skill 已经过测。
2. **实践积累 / Field notes**：团队公开使用过、具有实际产物与来源/审计记录的具体工作流，记录 `curation.track=practice`、`used_in` 与 `evidence[]`。要求能从公开仓库实际产物追溯使用记录。**代码已写好但没有运行记录、只有设想或教学示例，不能标为已实测**；公开产物证明曾应用，不等于独立效益评估。

未达到两类准入条件的原有模板、普通笔记、待验证 Skill 可保留源文件供进一步改进，但不得混进上述精选区。不擅自把用户私有仓库中的未发表论文、结果或过程迁入公开库。

**产品迭代优先级**：先精选作品/工具和证明复用收益，再做新的信息架构或组织治理；对视觉资产增加构图、科学表达、编辑性和真实尺寸可读性审美门槛。

## 组织定位与社区发展方向

**OpenResearchAssets 是独立的长期开放科研项目，不是创始人的个人作品集。** 让外部研究者记住并信任项目本身，以明确的准入标准、真实可复用的科研资产、透明的贡献机制积累公共价值。项目归属于 GitHub Organization [OpenResearchAssets](https://github.com/OpenResearchAssets)，当前采用**单一公开主仓库** [openresearchassets.github.io](https://github.com/OpenResearchAssets/openresearchassets.github.io) 和 [组织根域名网站](https://openresearchassets.github.io/)；Star、Issues、PR、代码和文档均围绕主仓库，不为表面规范提前拆分重复网站仓库。

![OpenResearchAssets 三阶段社区发展愿景](../assets/diagrams/community-trajectory.svg)

### 阶段一：有价值的开源项目

研究者能够发现资源、理解其适用条件、在真实研究任务中复用、核对效果。重点是**真实用户价值与独立项目认知**：实际使用、可验证的复用体验、来源与权限说明、稳定站点和低门槛的反馈入口。Star 代表关注，但不等于研究价值。

### 阶段二：有活力的开放社区

不同背景的研究者能够通过 Issue、PR 和公开讨论持续贡献、检查和改进资产、方法、工具及工作流。项目逐步培养可信任的 Maintainer，明确审核标准、贡献署名和权限边界；优先考察非创始人的持续贡献、审核质量和贡献者留存，而非形式上的社区规模。

### 阶段三：开放科研基础设施

在真实需求验证后，让结构化资产、元数据和复用标准能够跨项目和工具互通，形成科研工具、工作流、AI Agent 与社区贡献相互促进的生态。未来可能有独立模块或更多仓库，但只有在实际维护和协作需求出现时才拆分，不将未来能力包装成当前功能。

**阶段含义**：是发展愿景而非已完成里程碑、固定时间表或必然线性发展的承诺。科研真实性、版权授权、项目独立性、透明审查和中文为主英文为辅贯穿三个阶段。私有研发与未发表实验严格隔离，不自动公开。重要方向变更直接维护本文件及 README，不新增互相冲突的多版本计划。

## 长期目标：从研究资源收藏到任务级复用

**北极星目标：研究者只需把网站地址交给具备网页读取能力的 AI，并提供当前任务与必要权限，AI 就能自主定位与复用最相关的科研经验和工具，减少重复搜索、额外提示、人工介入、试错和 Token 消耗。**

覆盖科研完整生命周期：研究选题 → 文献调研 → 方法设计 → 实验实施 → 评估分析 → 论文写作 → 投稿展示 → 开源传播。资产既可以是论文视觉案例、优质项目主页，也可以是方法论、实验排错案例、工作流、工具、Skill、模板和能够直接编辑的源文件。不能让当前视觉素材的优势限制长期用途。

任何资产的目标是从「被看见」升级为「被发现 → 被理解 → 被选择 → 被真正使用 → 被验证」。单条记录要描述适用条件、可迁移原则、操作步骤或输入输出（适用时）、使用限制、官方来源和版权边界，避免成为只有链接或泛泛赞美的收藏夹。

**成功标准**：让同一类科研任务的检索命中率与最终结果质量更好，同时减少完成时间、Agent 不必要的上下文/Token 消耗与人工补充说明次数。应进行真实任务对照，严格区分「静态网站已经具备机器可读入口」与「有工具权限的 AI 在任务中确实取得收益」；后者尚未验证。

## 现在实际可用的功能

- [科研资产目录](../catalog/index.json)：以单一目录持续维护的视觉与技能资产，包含 Teaser、项目主页、原创 SVG、精选热门技能及有证据的实践流程；提供中英双语用途、来源和边界。
- [任务检索](../index.html#references)：当前支持本地文字匹配与阶段、领域、主题、资产类型组合筛选；Skills 还提供类型与双轨筛选，非向量语义搜索。
- [独立详情](../asset.html?id=supermimic-site)：使用条件、可学习点、风险、来源和相关资产。
- [AI 导航入口](../for-agents/) 和 [llms.txt](../llms.txt)：可公开抓取的指南与 JSON，不是自动执行科研任务的服务。
- 五份原创可编辑 SVG **概念**示意、浏览器人工自查清单以及供 AI 参考的质量检查 Skill。

## 已公开的真实论文证据链案例

[RoboRender 深度研究案例](../examples/roborender.html) 包含核对后的作者公开实验数据、[8 任务 CSV](../examples/roborender-results.csv)、[来源审查](../examples/roborender-provenance.md) 和两张本站原创可编辑分析 SVG。区分作者视频生成器的真实机器人视频训练与下游策略的模拟数据训练及零样本真机部署。**我们没有独立复现论文或产生新实验指标**；网页仅展示作者报告成果和明确的局限。

## 公开的贯通式教学案例（当前已提供）

目前另有 [三个真实可下载的实践教学案例](../examples/README.md)，围绕**虚构的二次视觉观察研究问题**，分别交付：方法流程图（原生 SVG）、可证伪 A/B/C 对照设计（SVG + 空白证据登记 CSV）、科研主页叙事（SVG + 可运行的示例 HTML）。这些并非新的自动科研服务，也**没有真实实验结果或经验证的性能提升**。相关文档和图形中英文均可用。正式研究的使用效果尚未开展独立评估。

## 核心原则

**经验必须可复用，科学事实必须保真，来源必须可追溯。** 专门研究质量提升的方法与 Skill，而不是仅建设大型 Benchmark；Benchmark/小规模用户研究用于独立评价实际收益。

资产类型可以扩展到研究选题、文献调研、方法设计、实验管理、评估、论文写作、展示和科研传播，但当前不存在的资产类别不宣传为已经完整覆盖。

## 未提供的能力

目前**没有**自动模型审图、上传 PDF 的云端科研助手、远程工作流执行、自动向量语义检索、收费产品或经过独立专家验证的质量模型。未来项目按实际需求与能力再决定。

**English:** A Chinese-first, research-lifecycle asset catalog with English metadata and human/agent-readable entry points. Current capabilities are static catalog search, original editable examples and a manual quality checklist. No hosted autonomous agent or automated image judge is deployed.

## 主题导航与能力资产精度（2026-10-26）

领域（学科与系统）、主题（研究问题与技术）、能力类型（Skill / Tool / Workflow）彼此正交，网站允许组合筛选，并向 AI 清单同步主题元数据。热门路线既允许收录广泛使用的科研相关开源工具，也允许**有明确 SKILL.md 深链接的独立技能**；后一种的 Star 数是母仓库 Star，不得表达为单项技能安装量。收录增加不改变原创实践的准入门槛，严禁把外部 GitHub Star 误写成我们的效果验证。首页默认精选预览，筛选后允许查看所有命中资源。

## Skill 信息密度与实际可用性（2026-10-26）

Card 要让用户看见**具体产出**和源文档入口，而不是只列项目名称；完整输入/依赖/步骤/验收仅放到详情页，避免主页卡片拥挤。官方源文件审阅和技术落地、效果验证是三个不同的核验层级，必须分开展示。审核台账由目录单事实源派生（`tools/audit_skill_intake.py`），不建立第二套可变目录。

# AI agent maintenance rules — OpenResearchAssets

This repository is a **quality-first public research design project**. Respect its scientific, visual, privacy and licensing constraints before making changes.

1. Keep `main` as one up-to-date canonical project. Do not proliferate `v2`, `latest-final`, duplicate gallery metadata or contradictory roadmap files.
2. Review actual files before changing them. Avoid broad aesthetic rewrites of existing figures without rendering and checking the revised layout.
3. **Scientific truth is the hard gate**: use real evidence, cite source data, mark conceptual figures, preserve numerical and textual claims across revisions. Never fabricate figures or accept visual appeal as scientific validation.
4. Curate third-party work through **source links and original editorial notes**. No scraped/copyrighted figure bulk download, fonts, private screenshots or unsupported licensing claims.
5. Original SVGs must remain genuinely editable and have a matching preview. Keep labels, shapes and arrows as independent objects where practical.
6. Use `data/references.js` as the only reference-card data source. Do not mirror it into Markdown tables or another site database. Update editorial text in place.
7. Do not publish or infer private repositories, manuscript drafts, unannounced work, model credentials, researcher identities or sensitive experimental results.
8. State honestly whether a workflow is manual, AI-assisted, experimentally validated or still a concept. The browser Quality Critic is manual in the current release.
9. Keep the free project substantive. Community-contributed open assets cannot be unilaterally converted into proprietary paid products.
10. After implementation run `python3 tests/check_project.py` and, when browser tooling is available, `python3 tests/browser_smoke.py`. Report exactly which checks ran and which were blocked. Check desktop and mobile layouts before public release.
11. Keep public-facing copy precise, minimal and aesthetically disciplined. A new feature must justify its complexity and privacy impact.
12. All new material should improve discoverability, research communication or practical reuse; fewer excellent entries are preferable to many unverified ones.
